If the language we were using to write our interpreter didn't have break statements then it seems like the proper way to do this is to use a parent-pointer tree, just like with variables. Every statement inside a loop has a pointer to that loop statement, but the pointers get "shadowed" by more recent loops so that statements inside nested loops only point to the loop that they're immediately inside of. Again, just like variable scope. The interpreter upon seeing a break statement checks its loop parent pointer and uses that to jump to the end of the loop (or if the pointer is null, gives an error.)

Java, however, has break statements. We don't want to reinvent the wheel. We'll simply have break statements toggle a bool "needToBreak" and during blocks / ifs / while loops we check if this bool is true, and if so we use Java's break (and then toggle the bool to false.) We don't need to consider for loops since they're just sugared while loops.

This works for runtime checking, but we'd ideally like to spot when breaks are used incorrectly, i.e. outside of loops, during parsing. Since we don't need the full parent-pointer tree structure, we just have a bool "inLoop" and check if it's true when we see a break statement. If it's false, give an error.
